# toki

A small website for free browser games, in English and German.

- **Accounts:** players sign up with a username, email and password. Sign-up, login and *Forgot your password?* show a Cloudflare Turnstile bot check (`src/lib/captcha.tsx`, site key `VITE_TURNSTILE_SITE_KEY` in `.env`); Supabase checks it when *Captcha protection* (Turnstile, with the widget's secret key) is on under Authentication → Attack Protection. Without a site key no check is shown. *Forgot your password?* on the login page sends a reset link that leads to `/reset-password`; logged-in players change their password on their account page. For the link to land on `/reset-password` directly, add `https://<your domain>/reset-password` to the redirect URLs in Supabase (Authentication → URL Configuration); otherwise Toki sends the player there itself.
- **Play:** anyone can play, without an account. Favorites and recently played are saved in the visitor's browser. For logged-in players, favorites (likes) belong to the account: a like counts once per account and shows on every device (`claim_likes` / `my_likes` in `supabase/schema.sql`).
- **Plays, playtime and likes:** a visit counts as a play after 10 seconds on a game's page (once per browser per game per day). Playtime is how long the game is on screen; the game page sends it when the player leaves, hides the app, or every 10 minutes (`src/lib/analytics.ts`), and the server never counts more than the time that really passed (`record_playtime`). Tapping the heart saves a game to Favorites and adds a public like. Developers see the last 30 days on *My games* and a stats page per game (`/game/<slug>/stats`: plays and playtime per day for 7 to 365 days, compared with the period before, update days marked, players, high scores, saves and open feedback). Rules: `supabase/migrations/20261118090000_playtime.sql`.
- **Add games:** only developers (creators and admins) can add games. *Add game* starts with the one-click way (`src/components/QuickAdd.tsx`): drop the game or pick its GitHub repository, the free AI reads its files and proposes the title, both descriptions, category, controls and score settings (`server/assist/scan.ts`), and one button puts it live. Saves work by themselves; if the game has a score, Toki Connect adds `toki.score` to its code: for an upload as the next live version (`server/connect/buildRepo.ts`), for a repository as a pull request. Admins choose which AI writes that code (free, strong or off) on the AI page. The ways underneath:
  - **Upload to Toki:** drop a ZIP, a folder or one HTML file (at most 100 MB). It goes straight from the browser to Cloudflare R2, and the game runs at its own address, `<game>.playtoki.app`, served by a small Cloudflare Worker (`cloudflare/games-worker/`), which also adds Toki's save script. The version before is kept 30 days for "roll back". Setup: [`docs/hosting-setup.md`](docs/hosting-setup.md). Server: `api/hosting.ts`, `server/hosting.ts`, `server/r2.ts`; rules: `supabase/migrations/20261115090000_game_hosting.sql`.
  - **From GitHub** (like Vercel): pick a repository, a branch and a folder; every push to that branch puts the new version live (the Toki GitHub App's push events, `server/gitDeploy.ts`).
  - **Upload keys** for AI agents, the upload script (`public/toki-upload.mjs`) and GitHub Actions, on *My games*. Agents read [`public/agents.md`](public/agents.md) (also linked from `/llms.txt`). A `toki.json` next to the game sets its title, controls, pictures and version; a new version posts an update for players.
  - **By link:** paste the address where the game runs (for example a Vercel or GitHub Pages site). When the game is updated there, Toki shows the new version automatically.

  - **Move to Toki:** a game added by link moves onto Toki with one button in its form (or *Move to Toki* on *My games*) and then works like a game that was on Toki from the start (`server/migrate.ts`). It needs GitHub connected and the game's repository picked (Toki preselects its guess: the one a GitHub Pages address names, else one named like the game or its site, preferring a published build like `<game>-web`):
    - The finished game is in the repository (GitHub Pages' `gh-pages` branch, or a folder with a playable `index.html`): Toki takes it from there, and every push updates the game.
    - The repository holds the source, which must be built first (Vite and the like, Godot): Toki's server copies the built game from its address right away (its page and every file of its folder that the page, scripts and styles point to, plus every picture, sound and data file the repository lists, since games often build those names while running), and the game follows the repository, built by GitHub Actions on every push (below).
    - Unity, GameMaker, Construct: their editor can't run on GitHub; the copy goes live, and new versions are uploaded (or exported into the repository, which Toki then follows).

    The game keeps its page, plays, likes, high scores and updates. Players' progress comes along by itself, however a linked game goes onto Toki (this button, an upload or "From GitHub"): Toki remembers the old address (`games.moved_from`, for 180 days), and the first time a player who played the game on Toki before opens it after the move, Toki opens the old address hidden, takes what the game's save script hands over there, and only then starts the game at its new address (`src/lib/movedSaves.ts`). So Toki first checks the old address: the save script must be there, and Godot and Unity games (which keep their files in IndexedDB) must also keep a copy of their progress in localStorage. Otherwise the developer sees how to fix it, or confirms that progress may stay behind. *Go back to the link* undoes the move. Rules: `supabase/migrations/20261119090000_move_to_toki.sql`.
  - **Built by GitHub Actions** (`server/gitBuild.ts`, `server/actionsAuth.ts`): a game whose repository holds its source gets one file, `.github/workflows/toki.yml`, through a pull request (or GitHub's "new file" page, filled in, when the Toki app may not change workflow files). On every push it runs `toki-upload.mjs --build`: installs the packages (npm, pnpm, yarn or bun), runs `build`, finds the built game and uploads it; Godot projects are exported with the project's Godot version. No key: the run asks GitHub for a signed token (`id-token: write`), and Toki accepts it only for the game that follows that repository and branch with `game_git.build = 'action'`. Rules: `supabase/migrations/20261120090000_github_build.sql`.

  *Fill in from a link* reads an itch.io page, a GitHub repository or any game page and fills in the form (`server/importer.ts`); the free AI then writes the English and German descriptions.
- **Developer accounts:** a player becomes a developer with an invite code, or by applying on *Become a developer* (`/apply`): they write what games they make and add links. Admins approve or decline (with a note) on *Applications* (`/applications`), and can take developer access away again (the games stay). One open application per account, at most 3 in 30 days. Rules: `supabase/migrations/20261109200000_developer_applications.sql` (it also undoes the per-game review from `20261109190000_game_review.sql`, which was live for a short time).
- **Invites:** admins create invite codes on the *Invites* page. Each code works once.
- **Toki Connect (AI):** developers connect Toki's GitHub App and let an AI add Toki saves and high scores to their game's repository (`/connect`). It reads the code, may ask the developer questions (e.g. what counts as the score), and opens a pull request. Admins pick the AI provider (an OpenAI-compatible endpoint or Anthropic), search its models, set prices, see the month's spending, and set quotas on *AI* (`/admin/ai`). Every call reserves its highest possible cost first, so a developer's monthly quota ($5 by default) and Toki's monthly cap ($20) can't be exceeded. Setup happens on the *AI* page itself (only the Supabase secret key goes into Vercel): [`docs/ai-setup.md`](docs/ai-setup.md). Rules: `supabase/migrations/20261110170000_ai.sql`; server code: `server/ai/`, `server/connect/`, `server/github.ts`, `api/ai.ts`, `api/github.ts`, `api/connect.ts`.
- **Free AI helpers:** next to Toki Connect's AI (the "strong AI", with prices and limits), admins can set up a "free AI" (an OpenAI-compatible endpoint where tokens cost nothing). It translates posts, replies, chat messages and game descriptions on request, points to similar feedback before posting, suggests games on the home page, drafts release notes and game descriptions, summarizes the feedback inbox and developer applications, turns a game's open feedback into a prompt for a coding AI (leaving out posts that don't help), answers players on a game's page ("Ask AI", from the developer's tips, what it learned from the game's GitHub repository, and the asking player's own progress: their save, best score and playtime), and does Toki Connect's easy steps. Buttons only show when the AI behind them is on. Each account may use each helper only so often an hour. "Fix with AI" on a bug report starts a Toki Connect run that fixes it. See [`docs/ai-setup.md`](docs/ai-setup.md); server code: `api/assist.ts`, `server/assist/`, `server/ai/free.ts`; rules: `supabase/migrations/20261112090000_free_ai.sql`.
- **Feedback:** every game has a feedback board (`/game/<slug>/feedback`), and Toki has its own (`/feedback`). Logged-in players post bug reports, ideas and other notes, reply, and vote. A bug report can be private: then only the reporter, the game's developer and admins see it. The developer (for Toki's board: admins) sets the status (open, planned, in progress, done, declined), replies with a *Developer* badge, and can hide posts. Developers see all feedback for their games in the *Feedback inbox* (`/feedback/inbox`); players see their own posts and replies on their account page. Posting is limited to 5 posts an hour and 20 a day per account, replies to 30 an hour (developers have no reply limit).
- **Updates (release notes):** a game's developer posts what changed in each version on the game's *Updates* page (`/game/<slug>/updates`); admins do the same for Toki (`/updates`). Notes are plain text, and lines starting with `-` become a list. When posting an update, the developer ticks the feedback it fixes: those posts are marked done and show "Fixed in 1.2" with a link to the update. The game page shows the latest update under *What's new*.

- **Profiles:** every account has a page at `/u/<username>` with an avatar (an uploaded picture, shrunk to 128 px in the browser, or a pixel avatar drawn from a seed), a short bio, their numbers (playtime, games played, best scores, favorites), their games, favorites and best scores. Friends also see whether they're online, which game they're playing and what they played lately and most.
- **Friends:** players send friend requests, which the other player accepts or declines (`/friends`). Blocking someone ends the friendship, stops requests and hides their messages.
- **Chat (`/chat`):** private messages between friends, group chats of friends (up to 20 people), a chat room on every game page and one public Toki room. At most 8 messages per 20 seconds and 200 an hour. Players report messages; admins handle reports on `/reports` (delete the message, or also ban the sender from chatting for a while). New messages arrive live (Supabase Realtime) while a chat is open.
- **Play together:** games with online rooms are marked *Multiplayer* in their form (a mark on the game's card, a filter on the home page). The game keeps its own multiplayer; Toki brings friends into the same room. The game tells Toki its room code with `toki.room(code)` (or the host types it), the host picks friends under *Invite friends* (also from the friends list and private chats), and an invited friend's game opens with the code in its address (`?room=CODE`, or the name set in the game's form). Invites show as a pop-up while the friend is on Toki and stay in the bell for 30 minutes. Code: `src/lib/invites.ts`, `src/components/GameInvite.tsx`; rules: `supabase/migrations/20261117090000_game_invites.sql`. Developers add it with Toki Connect ("Friend invites") or the instructions to copy; `select notify_developers('<topic>')` tells everyone with a game about something new for their games. Each such update is one entry in `src/lib/gameUpdates.ts`: the notification leads to its card under *Updates for your games* on *My games*, where every game it is for has a one-click *Update with Toki Connect* (a pull request to the repository the game follows, or a new live version for an uploaded game) and the instructions can be copied for an AI agent instead.
- **Parties:** friends who play together stay together. Whoever invites a friend leads a party, and a friend who accepts is in it (no extra step; at most 8 players). The leader's room is the party's room: when the leader opens another room, or another game, everyone else's Toki shows "Following @leader…" for a moment (with *Stay here*) and then opens that room. A bar under the top bar shows the party on every page, and the party's chat stands next to the game. A party ends once its players have left Toki. If the game set `toki.onHost(fn)`, Toki asks it to open a room when the player picks friends before one is open, so inviting is one step. *Share a link* in the invite window is for friends who aren't on Toki: the link opens the game in the room, and brings friends of a party member into the party. It works without an account too: a visitor plays in the room and is told what an account would keep (progress on all devices, high scores, staying together), and signing up from there leads back into the same room. Code: `src/lib/party.ts`, `src/components/Party.tsx`; rules: `supabase/migrations/20261122090000_parties.sql`.
- **Push for invites:** a friend who isn't on Toki gets a game invite as a notification on the devices where they turned on *Invites on this device* (the notifications page, or the invite window). Only invites are pushed. `public/sw.js` shows them, `api/push.ts` sends them (`server/push.ts`); the key pair that signs them is made on first use and stored with the server's other secrets (or set `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` in Vercel). On iPhone and iPad it needs Toki on the Home Screen. Rules: `supabase/migrations/20261122100000_push.sql`.
- **Notifications (`/notifications`):** replies to your feedback, status changes ("fixed in 1.2"), friend requests and accepts, being added to a group, game invites from friends, and losing a top-3 high score. New chat messages show as unread counts instead of notifications.
- **High scores:** games call `toki.score(points)` (from `public/toki-save.js`, times in milliseconds). Each player keeps their best score per game; the game page shows the top 10. The developer chooses whether higher or lower is better and can remove scores.
- **Search engines and AI search:** browsers get the app as it is. Crawlers, link previews and AI search (ChatGPT, Claude, Perplexity, …) get each public page with its title, description, picture, structured data (schema.org: the site, every game as a `VideoGame`, breadcrumbs) and a plain HTML version of its content, filled in by `middleware.ts` (`server/seo.ts`); a game that isn't there answers "not found". `/sitemap.xml` (`api/sitemap.ts`) and `/llms.txt` (`api/llms.ts`) list every game; `public/robots.txt` keeps private pages out.
- **Terms and privacy:** `/terms` and `/privacy` (`src/pages/Legal.tsx`, texts in `src/lib/i18n.tsx`), linked in the sidebar, the phone footer and the signup form.
- **Free plan:** old data is deleted on a schedule (`pg_cron`) so Toki fits Supabase's free plan: room messages after 7 days, private and group messages after 30 days, notifications after 30 days (and at most 100 per player), online status after 7 days, handled reports after 30 days, per-browser plays after 2 days and per-day game stats after 400 days (the totals stay), finished Toki Connect runs after 90 days and AI cost rows after 400 days (`cleanup_old_logs()`). Hosted games keep only the live version and the one before (30 days); the rest is deleted nightly from Cloudflare (`/api/hosting?action=sweep`). Game pictures are shrunk in the browser before upload (covers 1200 px, banners 2000 px, screenshots 1920 px, as WebP; GIFs stay as they are), and pictures a game no longer uses are deleted when it is saved or deleted (`src/lib/gameImages.ts`). Saves go up at most every 30 seconds while playing (at once when the page closes or is hidden), and not at all when nothing changed. Online status and the unread counts come in one request (`ping`) every 2 minutes; Realtime is only used while a chat is open.

## Tech

- Vite + React + TypeScript, hosted on Vercel (`vercel.json`)
- Supabase for logins, the games list, feedback and cover images. `supabase/schema.sql` holds everything up to the feedback system; newer changes are in `supabase/migrations/` (one file per change, applied in name order)
- Pixel-art covers are drawn in the browser (`src/pixel/scenes.ts`) when a game has no uploaded image
- `middleware.ts` fills in the title, description and image for link previews (WhatsApp, Discord, …). `api/og.ts` draws the preview image from the pixel cover
- `api/check.ts` tells members, while they fill in the game form, whether a game link can be shown inside Toki

## Checks

```sh
npm test          # unit tests and database tests
npm run typecheck
```

The database tests (`tests/db/`) run `supabase/schema.sql` and every migration in a real Postgres that runs inside the test process ([PGlite](https://pglite.dev)), then check the row level security rules as visitors, players, developers and admins. They need no Docker or Supabase account.

They also run on every pull request (`.github/workflows/ci.yml`).

## Run locally

```sh
npm install
npm run dev
```

The public Supabase URL and publishable key are in `.env`. They are safe to commit: what they can do is limited by the database's row level security rules.

## Games that need special browser settings

Most games need nothing. Games that use threads (Godot 4 exports with thread support, some Unity builds) only run with *cross-origin isolation*. For those, tick **“Needs cross-origin isolation”** in the game form. Only then does that game's page get

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: credentialless
```

(`middleware.ts`, and `vite.config.ts` for local runs). All other pages and games get neither header, because with them the browser only shows games whose own site sends matching headers.

The game's own site must then allow being embedded. Its responses need:

```
Cross-Origin-Resource-Policy: cross-origin
Cross-Origin-Embedder-Policy: require-corp
```

The game form checks this as soon as you paste a link, and lets you try the game right there.

If a game still won't load inside Toki, the game page has an "Open in new tab" link.

## Saves

Games that include `public/toki-save.js` send their localStorage to Toki (`src/lib/saves.ts`). For logged-in players:

- Toki answers the game's "hello" only once the account save is loaded or known to be missing, never with “nothing” while it is loading.
- A save only replaces the account save when it was made on top of it (`put_game_save` in `supabase/schema.sql`). A save from a device that had an older version, or none, never overwrites newer progress: the account copy stays, and the other one is kept as a conflict copy.
- Logging out sends nothing.
- Earlier versions are kept (`game_save_history`) and can be restored on the *Account* page for 3 days; older ones are deleted (daily `pg_cron` job and on every new copy) to save storage. Each game keeps at most 5 earlier versions and 3 conflict copies. A copy is kept every 30 minutes of play, when another device saves, and always right before a save shrinks to less than half its size (a "new game" or wipe).
- To put a save back, the script writes it into the game's storage and reloads the game. Script v2 ignores the game's own writes until the reload, because many games save their current state then (autosave, saving on close) and would write their fresh state over it. For games still on v1, when the first save after that reload is less than half the size of the save Toki gave, Toki keeps the progress, stores the new save only as a backup and offers "Load my progress".
